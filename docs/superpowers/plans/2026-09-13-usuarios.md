# Sección Usuarios (DNI + cambio de contraseña obligatorio) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `/usuarios` admin screen to list and create users, where a new user's initial password is their DNI and they're forced to change it on first login.

**Architecture:** Three new `User` columns (`dni`, `phone`, `mustChangePassword`) drive the whole feature. `mustChangePassword` travels inside the signed session JWT (no extra DB read on every request); a single check in `(app)/layout.tsx` redirects to `/cambiar-contrasena` whenever it's `true`. Server actions follow the exact patterns already used by `categories.ts` (FormData + `useActionState`, P2002 disambiguation) and `variants.ts` (constraint-index disambiguation helper).

**Tech Stack:** Next.js 16 (App Router, Server Actions), Prisma 7 + `@prisma/adapter-pg`, zod 4, bcryptjs, jose (JWT sessions), Vitest + Testing Library, Postgres in Docker for tests (`docker-compose.yml`, `.env.test`).

**Spec:** `docs/superpowers/specs/2026-09-13-usuarios-design.md`

## Global Constraints

- `dni` is `String?` (nullable) at the DB level — existing users (already in the real Neon database) have no DNI and must not break. Uniqueness still applies (`@unique` on a nullable column allows multiple `null`s in Postgres).
- DNI format: exactly 7 or 8 digits, validated with `/^\d{7,8}$/`.
- New password (on first-login change): minimum 6 characters, must match its confirmation field.
- Scope for this plan: **list + create** users, plus admin-triggered password reset. Editing an existing user's data or deactivating them is explicitly out of scope (per the spec's "Fuera de alcance").
- The full DNI is never returned by any read query — only a derived `hasDni: boolean`.
- Every server action that touches user data requires `requireRole('ADMIN')` from `@/server/auth/guards`, except `changePassword`, which only requires `requireUser()` (any logged-in user changes their own password).
- Tests run against the Docker test database (already wired up via `vitest.setup.ts` loading `.env.test`) — no test may touch the real `DATABASE_URL`.

- [ ] **Step 5: Write the action**

```ts
'use server'
import { revalidatePath } from 'next/cache'
import { Prisma } from '@prisma/client'
import { prisma } from '@/server/db'
import { requireRole } from '@/server/auth/guards'
import { hashPassword } from '@/server/auth/password'
import { createUserSchema } from '@/server/validation/user'

export type ActionResult = { ok: true } | { ok: false; error: string }

export async function createUser(_prev: unknown, formData: FormData): Promise<ActionResult> {
  await requireRole('ADMIN')
  const parsed = createUserSchema.safeParse({
    name: formData.get('name'),
    email: formData.get('email'),
    phone: formData.get('phone'),
    role: formData.get('role'),
    dni: formData.get('dni'),
  })
  if (!parsed.success) return { ok: false, error: parsed.error.issues[0].message }
  try {
    await prisma.user.create({
      data: { ...parsed.data, passwordHash: await hashPassword(parsed.data.dni), mustChangePassword: true },
    })
  } catch (e) {
    if (e instanceof Prisma.PrismaClientKnownRequestError && e.code === 'P2002') {
      // Same disambiguation approach as `variantP2002` in `src/server/actions/variants.ts`:
      // `@prisma/adapter-pg` doesn't populate `e.meta.target`, the real constraint name
      // lives at `e.meta.driverAdapterError.cause.constraint.index`.
      const idx = String(
        (e.meta as { driverAdapterError?: { cause?: { constraint?: { index?: string } } } })
          ?.driverAdapterError?.cause?.constraint?.index ?? '',
      )
      if (idx.includes('dni')) return { ok: false, error: 'Ya existe un usuario con ese DNI' }
      return { ok: false, error: 'Ya existe un usuario con ese email' }
    }
    throw e
  }
  revalidatePath('/usuarios')
  return { ok: true }
}
```

```ts
export async function resetUserPassword(id: string): Promise<ActionResult> {
  await requireRole('ADMIN')
  const user = await prisma.user.findUniqueOrThrow({ where: { id } })
  if (!user.dni) return { ok: false, error: 'Este usuario no tiene DNI cargado, no se puede resetear la contraseña' }
  await prisma.user.update({
    where: { id },
    data: { passwordHash: await hashPassword(user.dni), mustChangePassword: true },
  })
  revalidatePath('/usuarios')
  return { ok: true }
}
```

```ts
export async function changePassword(_prev: unknown, formData: FormData): Promise<{ error: string }> {
  const session = await requireUser()
  const parsed = changePasswordSchema.safeParse({
    password: formData.get('password'),
    confirmPassword: formData.get('confirmPassword'),
  })
  if (!parsed.success) return { error: parsed.error.issues[0].message }

  const passwordHash = await hashPassword(parsed.data.password)
  await prisma.user.update({ where: { id: session.sub }, data: { passwordHash, mustChangePassword: false } })
  await createSession({ sub: session.sub, role: session.role, name: session.name, mustChangePassword: false })
  redirect('/productos')
}
```

```tsx
'use client'
import { useActionState, useEffect, useRef } from 'react'
import { createUser, resetUserPassword } from '@/server/actions/users'
import { ROLES } from '@/lib/constants'
import { Input } from '@/components/ui/input'
import { Button } from '@/components/ui/button'
import { useToast } from '@/components/ui/toast'

type UserRow = {
  id: string
  name: string
  email: string
  phone: string | null
  role: 'ADMIN' | 'DEPOSITO'
  active: boolean
  hasDni: boolean
}

export function UserManager({ users }: { users: UserRow[] }) {
  const { toast } = useToast()
  const formRef = useRef<HTMLFormElement>(null)
  const [altaState, altaAction] = useActionState(createUser, undefined)

  useEffect(() => {
    if (!altaState) return
    if (altaState.ok) formRef.current?.reset()
    else toast(altaState.error, 'danger')
  }, [altaState, toast])

  async function handleReset(id: string) {
    const res = await resetUserPassword(id)
    if (res.ok) toast('Contraseña reseteada al DNI', 'success')
    else toast(res.error, 'danger')
  }

  return (
    <div className="flex flex-col gap-6">
      <form ref={formRef} action={altaAction} className="grid grid-cols-1 gap-3 md:grid-cols-2">
        <label className="flex flex-col gap-1">
          <span className="text-sm">Nombre</span>
          <Input name="name" required aria-label="Nombre" />
        </label>
        <label className="flex flex-col gap-1">
          <span className="text-sm">Email</span>
          <Input name="email" type="email" required aria-label="Email" />
        </label>
        <label className="flex flex-col gap-1">
          <span className="text-sm">Teléfono</span>
          <Input name="phone" aria-label="Teléfono" />
        </label>
        <label className="flex flex-col gap-1">
          <span className="text-sm">Rol</span>
          <select
            name="role"
            required
            defaultValue=""
            aria-label="Rol"
            className="w-full border border-border rounded px-3 min-h-11 text-base md:text-sm bg-transparent"
          >
            <option value="" disabled>Elegí un rol</option>
            {ROLES.map((r) => (
              <option key={r} value={r}>{r}</option>
            ))}
          </select>
        </label>
        <label className="flex flex-col gap-1 md:col-span-2">
          <span className="text-sm">DNI</span>
          <Input name="dni" required aria-label="DNI" inputMode="numeric" />
        </label>
        <div className="md:col-span-2">
          <Button type="submit" className="w-full md:w-auto">Crear usuario</Button>
        </div>
      </form>

      <ul className="flex flex-col divide-y divide-border">
        {users.map((u) => (
          <li key={u.id} className="flex flex-col gap-2 py-3 sm:flex-row sm:items-center sm:justify-between">
            <div className="flex flex-col">
              <span className="font-medium">{u.name}</span>
              <span className="text-sm text-muted">{u.email}{u.phone ? ` · ${u.phone}` : ''}</span>
            </div>
            <div className="flex items-center gap-2">
              <span className="text-sm text-muted">{u.role}</span>
              <span className={`text-sm ${u.active ? 'text-success' : 'text-danger'}`}>
                {u.active ? 'Activo' : 'Inactivo'}
              </span>
              <Button
                variant="ghost"
                size="sm"
                disabled={!u.hasDni}
                onClick={() => handleReset(u.id)}
              >
                Resetear contraseña ({u.name})
              </Button>
            </div>
          </li>
        ))}
      </ul>
    </div>
  )
}
```

Note: the button's accessible name is `Resetear contraseña (${u.name})` — this makes each row's button uniquely queryable by `getByRole('button', { name: ... })` in tests and for screen readers, matching the same disambiguation pattern already used by `QuantityStepper` (e.g. `Restar uno (fila 1)`).
